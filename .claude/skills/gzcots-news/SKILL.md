# gzcots-news

**类型**：学校新闻
**触发感**：建立机构权威（"我们和谁合作"、"我们办了什么大事"）
**自动化程度**：**半自动**。来源杂、信息靠口述、老板有自己的行文风格 + 会多次修改。
本 skill 只做信息整理 + 骨架占位，**正文留给老板**。

## ⚠️ 必须项（违反任意一条即审核红线）

- **信源白名单**：稿件若引用任何**政策措辞、行业数据、上位文件**（如"根据 XX 部 XX 号文"），来源必须在 `_shared/sources.yaml` 内；引用其他单位的活动新闻通稿，URL 必须在白名单（school_internal 或政府域名）或事先加白。
- **不强制 sub-agent 抓取**：本类的来源主体是主办单位内部通知和老板口述，通常公开网上查不到。如用户给了 URL，按下方 Research 节走 sub-agent。
- **先问 Q0**：本类 Q0 是"新闻面向哪类人"，与 fan/conv 不完全重合（详见 `_shared/article-goals.md` 末段）。
- **配图（inline）必须自动生成**：派 sub-agent 调 `scripts/gen-image.mjs --role inline`，产出 1 张"活动场景"装饰图。头图 ①、尾图 ⑨ **不替换**。详见 `_shared/image-generation.md`。**真实活动现场照（若老板提供）应优先用真照，配图是兜底**。

## 启动前置检查

同 `gzcots-publish/SKILL.md`。

## 输入：先 Q0，再 Q1–Q6

**Q0（必须最先问）** 本篇核心目的：
- A. **external_pr**（对外宣传，**默认推荐** —— 面向潜在 B/C 端客户，体现实力）
- B. **industry_rel**（行业关系，面向同行/协会单位，体现资源）
- C. **internal_celebrate**（内部喜讯，面向已有学员/合作方）

→ 三种目的的文体差异见 `_shared/article-goals.md` 末段 news 表。

**Q1** 已合并入 Q0。**跳过原 Q1**。

**Q2** 活动 / 事件主题（开放问答，1 句话）。

**Q3** 主办 / 承办 / 协办单位（列全，每家的全称必须准确 —— 错一个字老板会发火）。

**Q4** 参与人员 / 获奖人员（姓名 + 职务 + 单位）。

**Q5** 事件时间、地点。

**Q6** 老板特别交代要突出的点（开放问答）。如老板有原话，原话照填，**不要润色**。

## Research（条件触发）

- 默认**不抓**外部站点。
- 若用户给了 URL（例如某政府单位发的活动新闻通稿），按 `_shared/research-strategy.md` 派 sub-agent 抓一次作为**素材引用**：
  - 域名必须在 sources.yaml 白名单内，否则 abort 回报。
  - 输出 JSON 含活动名、主办单位全称、活动日期等结构化字段。
- 抓取结果**不作为正文主体**，只作为机构全称、日期等核对依据。
- **额外校验**：若 Q2–Q6 提到任何政策措辞（如"贯彻 XX 文件精神"），必须派 sub-agent 在 sources.yaml 内核对文件全称和文号，找不到原文 → 在 fill-in.md 标记 ⚠️ 待老板二次确认。

## 配图生成（必须 sub-agent · 仅 inline · 真照优先）

**优先级**：若老板提供了真实活动照片 / 合影 → 直接用真照，跳过本步。
否则派 `Agent` 调 `scripts/gen-image.mjs --role inline`：

- **inline × 1**：`--article-type news --audience mix --goal {Q0 映射 fan-like} --theme "{活动主题}"`
- `--style-extra` 贴活动性质：例如"几位中国职业培训学校工作人员在中式建筑入口前合影" / "签约仪式场景，两位代表握手"。**半正式合影感**，避免：举手欢呼、拉横幅、戴红领巾、举国旗。
- 头图 ①、尾图 ⑨ **不替换**。生成图按 ⑩ 块样式插在导语段之后、活动主体描述之前。
- 失败回退：跳过该位，告知老板需要补真照。

## 撰稿规则

- **不要替老板拿主意**。skill 只生成"占位骨架"，正文 60% 以上是空白引导字段。
- 句式倾向官方 / 正式（"在 XXX 单位主办、XXX 单位承办、XXX 单位协办的 XXX 大会上"），不要营销腔。
- 单位名称、人名、职务、奖项名称这些字段必须从 Q3/Q4 原样填入，不允许 skill 自己脑补。
- 老板交代要突出的点（Q6）以 ⑤ 重点卡片块单独成段。

按 Q0 切换：

- **external_pr**：标题可有传播力（如数字、级别词，**但禁广告法违禁词**）；结尾鼓励转发；可放小尺寸学校二维码（不放课程二维码）。
- **industry_rel**：标题完全正式（"XXX 单位与广建职校开展 XXX 交流"）；不放任何二维码；落款盖章感强。
- **internal_celebrate**：标题亲切（"恭喜！我们的 XXX 拿了 XXX 奖"）；可有适度感叹号；不放课程二维码。

## 生成的"半成品"

按 `_shared/135-editor.md` 骨架渲染，但正文段落用占位符标出**待老板补写**：

```html
<section style="...">
  <p style="margin:0 0 14px;">
    [待补：开场，背景介绍 1-2 句]
  </p>
</section>
<section style="...">
  <p style="margin:0 0 14px;">
    [待补：活动主体过程，1-2 段]
  </p>
</section>
```

必带块：①②③④⑨。`⑤` 重点卡片用于 Q6 的强调点。**不强加 CTA / B 端引流**（学校新闻不是营销稿）。

## 审核 / 输出

简化版审核（只跑维度 1 错字 + 维度 2 排版），**额外**检查：

- Q0 选项是否在 audit-report 头部记录。
- 若 Q0 = industry_rel，文中是否仍出现"立即咨询/扫码/课程"等营销词 → 必须报 ⚠️。
- 若稿中出现政策文件名 → sub-agent 是否已在 sources.yaml 内核对过？未核对的列入 fill-in.md 待办。
- 配图：若用了真照，需在 fill-in.md 注明照片版权来源（老板提供 / 单位授权）；若用 gen-image 生成，需老板目视确认场景与活动真实感不冲突（避免假合影对外宣传时的尴尬）。

输出双产物：
- `article.html`（半成品骨架）
- `fill-in.md`（待补段落清单 + 老板需要决定的事项列表 + 政策措辞待核对清单，便于打印或群里抄送）
