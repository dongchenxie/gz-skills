# gzcots-policy

**类型**：政策解读 + 营销
**触发感**：制造紧迫感（"政策窗口期"、"最高补贴"、"错过等一年"）

## 启动前置检查

调用前先按 `gzcots-publish/SKILL.md` 的"启动前置检查"确认 brand.yaml 头尾图已就绪。

## 输入：4 道必问

**Q1（必须先问 —— 决定全文话术）** 客户画像：
- A. **B 端：建筑施工企业**（主推：资质升级 / 批量培训 / 合规风险）
- B. **C 端：个人持证人员**（继教 / 学时 / 不被吊销）
- C. **C 端：考证求职者**（一/二建 / 求职 / 晋升）
- D. **C 端：蓝领工人**（技能证 / 补贴）
- E. **明 C 暗 B**：主线写给个人看，结尾强引流 B 端合作

**Q2** 政策原文 URL（必填）。如果用户只给标题没有 URL，先到 `_shared/sources.yaml` 列出的官方源里搜索匹配项。

**Q3** 关联推销的课程（多选，从 `_shared/courses.yaml` 的 categories 列表选）。

**Q4** 紧迫感等级：高（"最高补贴，不要错过"）/ 中（"近期窗口"）/ 低（"建议关注"）。

## 抓取（必须在 subagent 里完成）

用 `Agent` tool（`subagent_type: general-purpose`）派一个子 agent，让它：

1. 优先尝试用 `WebFetch` 直接抓 Q2 的 URL。
2. 如返回 403 / 302 到登录页 / 内容明显被截断，**自动切换到 Playwright MCP**（`mcp__playwright__browser_navigate` → `_snapshot` / `_text`）。
3. 提取：政策标题、发文机关、发文日期、生效日期、关键条款、关键数字（金额 / 人数 / 期限）、适用人群。
4. 校验：URL 域名必须在 `_shared/sources.yaml` 列出的政府域名里，否则报错退出。
5. **只把结构化提取结果返回主上下文**（JSON 即可），不要把原文 HTML 倒灌回来。

## 撰稿规则

按 Q1 的客户画像切换话术：

- **B 端**：开头切入"对企业意味着什么"（资质门槛、合规风险、人员配齐压力）。引用条款时偏向"企业责任"条款。CTA 用 `courses.yaml` 里的 `cta_b` + `cta_elements.b_handoff`。
- **C 端持证**：开头切入"你的证还安全吗"。强调继教 / 学时。CTA 用 `cta_c`。
- **C 端考证**：开头切入"政策红利窗口期"。强调拿证后的收入 / 岗位增量。CTA 用 `cta_c`。
- **C 端工人**：白话、短句、强调"几月几号截止"、"最高拿多少钱"。
- **明 C 暗 B**：主线 C 端，但在结尾加 ⑧ B 端引流块。

通用规则：

- "从学员角度出发"先讲利益、再讲流程、最后才是课程。
- 政策原文条款用 ⑤ 重点卡片块呈现，避免大段引用让读者跳过。
- 关键日期、金额必须和子 agent 返回的结构化数据一致。任何虚构数字都属于红线违规。

## 渲染

按 `_shared/135-editor.md` 的通用骨架渲染 HTML。本类推文必带块：①②③④⑤⑥⑦⑨；C 端推文额外必带 ⑧。

## 审核

按 `_shared/audit-checklist.md` 跑 5 维自动审核，输出 markdown 表格。

## 最终输出

向用户返回**两份**产物：

```
=== article.html ===
<完整 HTML，可直接粘到 135 编辑器>

=== audit-report.md ===
<5 维审核表 + 必须人工二次确认清单>
```

**不要替用户点"发布"**。skill 在审核报告输出后即停止。
